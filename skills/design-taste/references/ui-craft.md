# Interactive UI Craft
> **Status: default guidance. Not yet validated by Anthony's comparison rounds.** Follow these as defaults for surfaces his validated rules (`principles/*.md`, SKILL.md) don't cover. Wherever they conflict with a validated rule, a dealbreaker, or a non-negotiable, the validated rule wins.
> **Read when:** building or critiquing web or app UI (dashboards, forms, lists, settings, onboarding, landing pages with interactive parts); designing hover/focus/loading/error behavior; stress-testing with worst-case content; drag, swipe and sheet behavior; web on phones (viewport, safe areas, tap and zoom quirks); adding motion to an interface or diagnosing dropped frames; writing interface copy or sample content; filling a mock with data, names, numbers or images.


## The five states
- Design every surface that fetches, lists or accepts data in five states: loading, empty, error, populated, edge. A mock that shows only the populated state is unfinished, because the other four are where users spend their worst moments. `L1` · default
- When delivering working UI, wire and exercise the transitions among those states. One active state at a time must be visible; buttons that do nothing and loading/empty/error copy shown simultaneously do not satisfy the state design. For a design-only mock, label the states as proposed views. `L1` · default
- Edge means the worst plausible content: the longest title, a missing image or optional field, zero and thousands of items, a single-character query, text in another script or direction. Truncate on purpose with a visible affordance (clamp, ellipsis plus full text on demand); never let the layout break. `L1` · default. For the name that identifies a row: widen the column if there is room, otherwise wrap; a middle cut with a pause-on-hover tooltip (also on focus and tap) is the fallback, and an end cut is never used when names differ near their end. `L1` · R162
- Empty state has a job: say what this place is for, why it is empty, and offer the one next action. First-use empties are the onboarding moment; no-results echoes the query and offers a way out; a cleared list gets a short calm note. Never a blank panel or "No data". Build it type-led (or with concept-specific imagery); no stock or generic illustration. `L1` · default
- Error is its own state: never reuse the empty layout, and never let a failed fetch masquerade as "nothing here". `L1` · default
- A refresh failure must not erase records already on screen. Keep the last known content, show an error near the affected region, and give a retry action. A first-load failure can use the full error state. `L1` · default
- Error copy has three parts: what happened, why if it is knowable, what to do next. Name the specific cause, keep everything the user entered, and offer the recovery action in place. Not "Something went wrong"; no "Oops"; no blame. `L1` · default
- Choose loading treatment by expected wait, not by habit. Reference floors: under about 300 ms show nothing (a flash of loader is worse than the wait); to a couple of seconds a quiet in-place indicator; a few seconds up to about ten, a skeleton shaped like the real layout, or a labelled spinner for a single control; longer, determinate progress with cancel; past about a minute stop animating and offer retry, cancel or continue. `L1` · default
- Prefer a skeleton to a spinner when the final layout is known: it reserves the space so nothing jumps when content lands. Skeleton fills are flat tonal blocks; any pulse or sweep is quiet, stops the instant content arrives, and is static under reduced motion. Never replace stable chrome with a full-page loader for a partial fetch. Never an unbounded spinner. `L1` · default
- Success messages are plain statements of what changed, with no exclamation marks. One celebratory moment, if any, belongs at the end of a flow, restrained and one-shot; keep the middle of a flow calm. `L1` · default

## Worst-case content (stress the design before the data does)
> Adopted from field review (emilkowalski/skills, break-ui). The reasons are the source's, not Anthony's; they stay `default` until he answers.
- Test with the worst believable value, not the kindest one. Demo data is picked, without anyone deciding to, so the design looks good: names that fit one line, every optional field filled, counts that never need a separator. The first time a real long name or an empty field turns up is in production. `L1` · default
- A worst case must be believable or limit-backed: a real naming pattern, or the actual limit the field's schema or column allows. If no limit exists, that is itself a finding to report. A keyboard-mash string proves nothing and gets dismissed, so it teaches nothing. `L1` · default
- Feed the worst case through the same door the demo data uses (the fixture, the mock, the props) and mix the failures across rows, the way real data mixes them. Hand-editing the layout to force a break tests the edit, not the design. `L1` · default
- Short breaks as often as long. A one-letter name leaves a column empty; a count of exactly one exposes a hard-coded plural; a missing optional field leaves an orphaned dash or an empty line; a translated label runs longer than the English one it was drawn around. Plural forms follow the language, initials come from whole characters (accents, emoji and non-Latin scripts do not split cleanly) with a neutral fallback mark, and numbers are formatted for the reader's locale and guarded against empty values. A missing optional field drops its line unless the space is reserved on purpose. `L1` · default
- Decide per field how overlong text yields; one global rule is wrong somewhere. Wrap what identifies (names, titles in a detail view). Cut at the end what is secondary and front-loaded (a description, a message preview). Cut in the middle what differs at the end (file names, emails on a shared long domain, paths, ids), because end-cutting makes them look identical. Clamp multi-line previews so card heights stay predictable. Never cut a number, an amount, a date or anything the reader compares. Every cut keeps a way to read the full value. `L1` · default
- Settle who yields when space runs out. Text that can wrap or cut gives way; the parts that identify or act (the avatar, the status mark, the trailing menu) keep their size and stay reachable. Strings with no break opportunity (emails, URLs, ids) need one provided; a fixed-size mark never shrinks to make room for words. `L1` · default
- Re-check the stressed content at the real container width (a list in a narrow sidebar is not a full-page list), at the narrowest and widest supported widths, with enlarged text, in dark, in right-to-left, and with no hover. Text grows and boxes do not. `L1` · default
- When reporting a stress test, rank by consequence: broken (unreadable, unreachable or wrong), ugly (readable but visibly off), fragile (fine now, one realistic step from breaking: no limit, no fallback). Put choices with more than one right answer to the user with a recommendation instead of silently choosing, and list what held up so a sturdy component is a good result, not an empty report. Keep the worst-case dataset beside the demo one as a regression check, dev-only. `L1` · default

## Accessibility baseline beyond contrast
- Reference standard for UI: WCAG 2.2 AA. Anything below it is debt; flag it to the user. `L1` · default
- Every interactive element has a visible keyboard-focus state, distinct from hover. Draw it as a flat outline offset outside the box so layout never shifts. This is a structural affordance, not decoration, so it is not a glow or drop shadow. Never remove the browser outline without a replacement at least as visible. Reference floor: 3:1 against what it sits on, and thicker than a hairline. `L1` · default
- The 3:1 floor extends to anything the user must find or operate: input outlines, icon-only controls, toggle tracks, chart marks against their ground. Text contrast alone does not make a control findable. `L1` · default
- Never carry a state or category by hue alone, or by motion alone. Pair color with a second channel: label, icon, shape, weight, position, underline. (For ordinary paragraph links, color plus underline is the validated treatment; navigation and control-like links use different cues, R155.) Status colors stay a small separate set, never the brand accent. `L1` · default
- Targets: reference floors, 24 px minimum and about 44 px for primary and touch-first controls, with separation so neighbouring hit areas never touch. Grow the hit area with padding, not the glyph; thin line icons stay thin. Primary actions never lean on a size exception. `L1` · default
- Any control may be custom-drawn (his stated answer, not yet a comparison round), but a custom control must replicate everything the native one provides: the right role and accessible name, every state, full keyboard operation, visible focus, and the same submitted value. Where a native element already does the job and no design reason argues otherwise, using it is still the cheaper way to meet that bar. DOM order equals visual reading order; never reorder with positive tab indexes. Add ARIA only where the role is not already carried by the element. `L1` · default
- Heading level follows document structure; its visual size follows the type hierarchy. The two are independent. Content images and charts carry a text alternative (for a chart, state its takeaway); decorative marks get none. Declare the document language. Icon-only controls get an accessible name. `L1` · default
- Reduced motion: every movement has a variant that removes travel, scale, rotation and parallax and keeps a short opacity or color change, so the state change still reads. Gentler, not zero. Gate hover motion to devices that hover. `L1` · default
- Vestibular and light sensitivity reach past travel. A moving full-viewport background, a slow looping oscillation and an abrupt brightness jump (a theme switch that flashes white) all bother people who never tripped the reduced-motion rule. Ease a light-to-dark change, keep large moving surfaces calm while they travel, and give ambient motion a still option. `L1` · default (adopted from field review)
- Flash limit, for UI and for MP4 alike: reference floor, never more than three flashes in any one second. No strobing cuts or rapid full-frame luminance swaps. `L1` · default

## Forms
- Visible label above every field, always. A placeholder is an example, never the label, because it vanishes when typing starts. Helper text sits between label and field when needed. Mark optional rather than required when most fields are required; say which convention once at the top. `L1` · default
- Validation timing: no error while the user is first typing in a field; check when they leave it. Once a field shows an error, re-check on every change so the error disappears the instant the value is valid. Untouched fields never show error or success styling, so nothing is red on first load. `L1` · default
- Error placement: beside or directly under its field, specific to the rule that failed, with the fix when it is determinable. On submit, move focus to the first problem; long forms add a linked summary at the top, shown on submit only. Never a generic "Invalid input". `L1` · default
- Match input type and keyboard to the data. Numeric identifiers (postal code, one-time code, card) are text fields with a numeric keypad hint, never spinner number fields, which strip leading zeros. Allow autofill. Accept messy input (spaces, dashes), normalise it, display one canonical format. `L1` · default
- Submit shows pending on the button itself, locks re-submission, and confirms the outcome in text. Never clear fields because an unrelated error occurred. Do not make users retype what they already gave in the same flow. `L1` · default
- Destructive, financial or legal actions are undoable, or get a review step that restates exactly what will happen. `L1` · default
- One primary action per view; its label is specific ("Save API key", not "Continue") and fits on one line. One label per intent across the page. Never two solid buttons for the same action in one viewport. `L1` · default

## Interaction states
- Every control defines hover, focus-visible, pressed, disabled and loading, and equivalent controls share one treatment everywhere. Inconsistent states teach users nothing. `L1` · default
- Hover and pressed states transition on the house ease-out; they never swap instantly and never merely dim or grey the text. Pressed reads as a tone or fill change; a tiny scale-down is optional, not required. Do not animate text weight or box size on hover in a way that shifts neighbouring layout (his validated card lift is the exception: rise, slight scale and shadow, out of flow). `L1` · default
- Shadows exist to establish z-depth and are subtle, neutral and soft: on hover and drag states, on cards raised above the page, on floating layers (menus, popovers, dialogs) and on sticky headers and bars. Never bevel, emboss, glow, colored or heavy shadows, nor decorative shadows with no depth job. A subtle shadow on text is acceptable when it helps legibility: alone over mild imagery, but over a busy photo a scrim or panel comes first (R064, R071 stand). His stated answer, which widens the old "hover elevation is the only shadow" rule; not yet a comparison round. `L1` · default
- Text in a row of figures aligns: numbers that stack in columns or sit side by side (metrics, tables, dates, versions, page numbers) align on the right and use consistent precision (R154). Tabular figures are a `default` implementation; a lone number in a sentence stays proportional. If the chosen face lacks tabular figures, change the face for the numeric tier. `L1` · R154 for alignment and precision; other details `default`

## UI motion
- Motion has a job: orient the user across a change of place, time or state, or confirm an action. Decoration, "premium feel" and filling silence are not jobs. `L1` · default
- Motion has a gate: ask whether to animate at all. The right answer is sometimes no motion and zero lines of animation code. Decide that first, then choose the effect. `L1` · default (adopted from field review)
- Motion claimed, motion shown: if the system sentence promises motion above state changes, the build must actually move (entrances, reveals, hover feedback) and you must see it work. If you cannot ship working motion in scope, lower the claim and ship a clean static piece. Half-built motion that clips or jumps is worse than none. `L1` · default (adopted from field review)
- Frequency gate: the more often someone sees an effect, the shorter and quieter it is. Keyboard-driven and constantly repeated actions get none; occasional surfaces (menus, dialogs, toasts) get a standard transition; only rare, first-time moments may be more expressive. `L1` · default
- Duration tiers, reference floors for interactive UI only: pressed feedback near-instant (about 100 ms), standard state change about 150 ms, entering surfaces about 200 to 300 ms, cross-screen up to about 500 ms. Exits run shorter than entrances (roughly 0.7x; unvalidated, validation queue 3). Shorten on small screens. These do not apply to video or staged motion graphics. `L1` · default
- Easing: entrances and exits ease out; on-screen moves also ease out with a soft end. Anything that answers the person's action (menus, popovers, side panels, dialogs) opens on a strong ease-out, with nearly all the travel at once and a long soft finish, because it feels faster; composed entrances that arrive on their own (a welcome card, a staged sequence) keep the moderate house curve so they land gently. The trigger decides, not size or frequency (R164, R165); a determinate progress fill that tracks real progress may be linear (a gauge, not a design element; marquees and tickers are not used); never ease in on entrances, since it delays the moment the user is watching. Whether exits should accelerate away (as his motion rules suggest for staged motion) is unvalidated for UI (see `validation-queue.md` item 2); until then exits ease out. No overshoot, no spring outside the playful tone. `L1` · default
- Never grow an element from nothing. Entering surfaces start near full size with opacity (or just fade and rise slightly), and popovers originate at their trigger while dialogs stay centered on their own axis. `L1` · default
- Applying a motion recipe never rewrites the product's copy: use the existing text, and use sample copy only for a standalone demo. Replacing one text with another (a state change) is its own choreography, different from a first-load reveal; the former should be quick and quiet. Frame work stays within budget: a movement that drops frames on a mid-range phone is cut, not tuned. `L1` · default

- Interruptible by default. Anything a person can trigger again before the last change finishes (a toast stack, a toggle, an expand and collapse, the release of a drag) must retarget from where the element is now. Restarting from the beginning reads as a glitch and finishing first reads as lag. Why: thought and gesture run in parallel, so a locked interface feels like it is not listening. Prefer a transition that can be redirected to a scripted sequence that cannot; keep scripted sequences for one-shot events nobody repeats. `L1` · R163 (retarget beat jump and finish-first on a sliding panel; toast stacks and drags not tested)
- Slow where the person is deciding, fast where the system is answering. A hold-to-confirm fill takes its time because the wait is the safeguard, and releases at once because letting go is the system answering. The same shape fits any deliberate act: the deliberate phase can be slow, the response never is. `L1` · default (adopted from field review)
- Speed of motion is speed of the product. Quicker motion makes the same wait feel shorter, and a warm-up helps: once one hint or tooltip is open, its neighbours open at once with no delay and no transition, because the delay existed to prevent accidental opening and has already done that job. `L1` · R161 (the warm-up; the motion-speed claim remains a default)
- A surface leaves the way it came. Entering and leaving along one path, from one origin, keeps the person's map of where things live, and is why swiping it away feels obvious. Navigation carries direction too: forward and back travel opposite ways so place has a sense of before and after. This governs interactive surfaces; staged sequences keep the handoff rules in `principles/motion.md`. `L1` · default (adopted from field review)
- When one state replaces another in the same spot, a straight crossfade shows two objects at once. Shorten the overlap or shrink the travel first. A brief blur to fuse them is a fix others use; it is not adopted here until it is tested (validation queue 5). `L1` · default
- Decorative motion may borrow momentum; functional readouts may not. A flourish that follows the pointer with a little weight is acceptable on a showpiece page; the same easing on a chart, a balance or a number being read for a decision is noise. Data being read or acted on does not move for style. `L1` · default (adopted from field review)
- When motion drops frames, name the cause before touching code. Likely causes, in the order they usually occur: an animated property that forces re-layout or repaint where a cheaper one looks the same (scale in place of size, translate in place of position, opacity in place of show and hide, a shadow filter in place of an animated shadow); the page doing heavy work at that moment (a route change, a fetch, a mount), when work that can run off the main thread should; state updated every frame; a value inherited by many descendants changing every frame; a heavy blur. Promoting a layer in advance is the last step, only after a shift or a measured drop, since each promoted layer costs memory. Name properties explicitly in transitions; "all" animates whatever changes next. The developer's machine is the least representative device it will run on, and a high-refresh screen halves the frame budget. Verify on a mid-range phone, not by feel. `L1` · default (adopted from field review)

## Content integrity
- Never invent statistics, testimonials, awards, ratings, logos, customer names, prices or citations. Use real or user-supplied facts, or a clearly labelled placeholder, or leave the slot out. A figure shown carries its source, unit and period. `L1` · default
- For missing quantitative data, a slot names the required field, unit and period without implying a value or trend. Do not draw a plausible line or bar pattern behind placeholder labels: its direction still tells an unsupported story. Keep the chart scaffold if it helps show where verified data will go. `L1` · R152 application
- No lorem ipsum, no "Feature one / two / three". Write real draft copy. An empty-feeling section is a composition problem to fix with layout, not to pad with words; do not add sections or copy the user did not request without asking (if you cannot ask, state the assumption). `L1` · default
- Name a real-world thing (person, product, cover, artwork, landmark, brand mark) and it gets its real image, confirmed to depict it; never a generated or look-alike substitute. If the right asset is unobtainable, show an honestly labelled placeholder and say so; never ship a fake or a bare grey box. Generation is for subjects with no real referent. `L1` · default
- Interface copy: concrete verbs, active voice, sentence case, one register per page; specific microcopy over generic ("Start tracking", not "Get started"). Skip hype and filler words (seamless, unleash, next-gen). Testimonials run to a few lines with name and role. `L1` · default
- Specificity test: with the logo removed, could this belong to any product in its category? If yes it is a template; change the section order or add one section only this product would have. Keep designer, presenter or "demo" controls out of the product artifact. `L1` · default

## Laws of UX that change output
- Fitts: speed depends on size and distance, so frequent and primary targets are larger and closer to where the pointer or thumb already is; spacing between hit zones matters as much as size. `L1` · default
- Hick: every added equal option slows the decision. A decision screen has one visually dominant recommended option and a small number of equals (roughly three to five); the long tail goes behind disclosure. Mark exactly one recommended item in a set; visual weight matches intended decision weight. `L1` · default
- Proximity first, then similarity, then common region, then connection. Gaps between groups are a clear multiple of gaps within (reference starting ratio, about 3 to 4x); uniform spacing groups nothing. Enclose only when space and alignment are not enough, because boxing every section erases the signal. Equivalent elements share one treatment; the single deviation marks the active or recommended one. `L1` · default
- Miller, correctly read: working memory holds a few chunks, not a menu length. Chunk long lists into named groups; show state on screen (applied filters, selected, visited) instead of making people remember; put the key items at the ends of a row. `L1` · default
- Jakob: default to the category's convention for position, icon and behavior. Depart only where the departure is deliberate and pays for itself; put help at the point of action. This is the UI corollary of "deviate decisively or not at all". `L1` · default
- Goal gradient: multi-step flows show real position ("2 of 5"); never fabricate progress or streak pressure. `L1` · default
- Simplicity is not minimalism. Burying everything behind one control looks sparse and is not simple. Strip what is unnecessary, show the common path first with advanced options one level deeper, and add context when it removes work (a scrubber that shows time remaining). `L1` · default (adopted from field review)
- Mapping: place a control next to what it affects and arrange controls to mirror what they change. If a label is needed to explain what a control does, the mapping is weak. Name navigation for what it holds ("Library", "Progress"), not with umbrella words that could mean anything ("Home"). `L1` · default (adopted from field review)
- Every screen answers where am I, where can I go, what is here and how do I get out, and never traps the person. Feedback comes in four kinds, each in its own place: status (something ongoing), completion, warning (before a problem) and error. `L1` · default (adopted from field review)
- Confirmation dialogs are for the irreversible; one on everything trains people to click through. Prefer undo, and let a slip-prone irreversible action require a deliberate act (a hold) instead of another dialog. `L1` · default (adopted from field review)
- Do not misuse the laws. Miller's number is not a seven-item cap on navigation (menus work by recognition). Hick's law is not a reason to delete options: novices scan linearly, so group and add search instead. The Zeigarnik effect is not a basis for nag or reminder features. The Doherty threshold is not an excuse to add delay so work seems valuable. Choice overload depends on conditions, so do not hard-cap catalog or result counts on its authority. A pretty design is not proof it is usable. `L1` · default

## Interface typeface
- Interface typefaces follow the brand file. Where the brand names a heading face, use it on product screens too; where there is no brand, use one neutral sans family and let weight and size carry hierarchy. Do not add a display face to product screens on your own. Stated preference from Anthony, not yet tested in a comparison round. `L1` · default
- Interface type responds to size and to the person's settings. Large display text can sit slightly tighter and a heading's leading tracks its size, so one fixed letter-spacing or line height is wrong somewhere. Spacing that belongs to the text (padding, gaps beside it) is in units that scale with the text, so a larger text-size setting does not break the layout. Small text stays at the face's own spacing: opening up lowercase is a dealbreaker here, whatever other guidance says. `L1` · default (adopted from field review)

## Control and component geometry
- A field's border keeps one width in every state. Express focus with an offset outline in a reserved slot, not a thicker border, so nothing shifts by a pixel when focus lands. Focus appears instantly; a ring that fades in is late exactly when the keyboard user needs it. Show it for keyboard focus only, never after a mouse click. `L1` · default
- A text field and the button beside it share one height, and density variants step together (compact, regular, roomy) so a row of mixed controls stays level. `L1` · default
- Helper and error text own a reserved line, so a message appearing does not push the form down. Disabled is stated three ways at once: visibly muted, a not-allowed cursor, and truly disabled for the keyboard. Opacity alone is a look, not a state. A read-only field can still be focused and copied; a disabled one cannot. `L1` · default
- Error travels on three channels together: color, a supporting sentence, and the programmatic invalid state. Color alone fails. `L1` · default
- Every control that can be selected has a persistent selected mark (ring, check, rule or fill) that differs from the hover cue. Hover that merely nudges position is not a state. Selection and the primary call to action never both take a full accent fill on one screen. `L1` · default
- Form controls (selects, checkboxes, radios, ranges) are fully custom, drawn from the page's tokens, never the browser's default look. A custom control still earns its place by matching the native one's behavior: the real role and state exposed to assistive tech (or a hidden native input kept in sync), full keyboard operation, a visible focus ring, and a form value that submits. A select follows the combobox keyboard model (open, type-ahead, Home/End, Escape cancels, Enter commits). Stated preference from Anthony, not yet tested in a comparison round. `L1` · default
- Roles are not mixed in one component: a filter chip, an input chip, a dismissible chip and a static badge behave differently. A static badge is never clickable. A chip may look compact, but its hit area still reaches the target floor; a dismiss icon takes its own focus and state. `L1` · default
- Card anatomy is spaced by meaning, not uniformly: the identifying name and the price sit closest together, secondary meta follows, and the action is separated by the largest step or a rule. Media and text share one width, and the image edge, text edge and action edge line up. One clickable region per card: a whole-card link or an inner action, not both competing. `L1` · default
- Choose surface treatments (hairline-ruled bands, flat ink plates, soft raised tiles) deliberately, one per role, and hold each role the same everywhere. Mixing treatments in one product is fine when each has a reason and each role is consistent (R159: one treatment per role beat the same box everywhere; reasons: one box looks assembled from a kit, and different roles should look different so people know what each is). What fails is the same rounded-corner-plus-border box stamped on cards, banners, dialogs and inputs alike with no reason, which is a widget kit, not a design. Match treatment to domain: shopping surfaces want bounded cards with a dominant price, operations tools want compact rows and status badges, reading surfaces want rules and a long measure. `L1` · default
- Empty states and dialogs are their own surfaces (a distinct container, or the native dialog with a styled backdrop), not a muted paragraph inside the card they interrupt. `L1` · default
- Carousels are short (a handful of slides at most), keep their controls inside the frame, and pause when the user needs them to. A master-detail view shows one pane on narrow screens and two only when wide. Decorative layout pieces are hidden from assistive tech, and reading order matches DOM order. `L1` · default

## Hover, touch and what moves on its own
- Hover amplifies; it never gates. Nothing a visitor needs may be reachable only by hovering, and on touch or keyboard-only use the hover layer should already be in its open state. Cap hover at a small lift or tone shift, or a pause. Reason: gated content cannot be compared, is lost on touch and keyboard, and makes the visitor hunt; it flips only when the extra is truly optional. This includes secondary details that help decide; a tooltip's content must also show on keyboard focus and by tap. `L1` · R156, R161
- Anything that opens on interaction opens once and stays: a panel that snaps shut when the pointer drifts teaches people to hold still. Opening on view, or on click or tap, persists until an explicit close (second click, click elsewhere, Escape) (R156). Reason: a vanishing panel cannot be read or reached, persistence keeps the person in control, and click-to-open is one behavior across touch, mouse and keyboard. Menus open on click (or tap, or keyboard) only, even on devices that hover: in R161 click-only beat both hover-open variants for a navigation menu, because it is predictable and sets one way to reach a menu on every device. `L1` · R156, R161
- Automatic motion passes a four-part test before it ships: the repeated item is one of many equivalents (nothing unique is lost if you miss it); the same content has a still route; the user can pause or slow it; and it arrives without effort. Motion that changes what can be seen is a gate; motion that changes only how it looks is decoration. `L1` · default
- A reveal-on-scroll plays once, on content that is not a task screen, and never replays body copy. Reveal with opacity and a small travel, not clips or blurs. `L1` · default
- Separate keyboard and mouse intent for route changes: moving focus to the new page's heading is right, but the visible ring should not draw a box around a title the user never tabbed to. `L1` · default

## Drag, gesture and feel
> Adopted from field review (emilkowalski/skills; Apple's fluid-interface talks as that source distills them). Reasons are the sources', not Anthony's. This applies where a person's hand is on the element; staged motion is governed by `principles/motion.md`.
- Respond at the press, not the release. Feedback that waits for the finger to leave reads as lag even when it is instant, and removing the tap flash only works if every tappable thing has its own pressed state. During a drag, feedback is continuous: the element tracks the hand the whole way, not only when the gesture completes. Why: directness collapses the moment a delay appears. `L1` · default
- Direct manipulation is one-to-one and keeps the grab. An element moves with the hand, and respects where it was grabbed instead of jumping its center under the finger. Tracking survives the pointer leaving the element's bounds, and a second finger arriving mid-drag is ignored. `L1` · default
- Release continues the hand, it does not restart. The motion after letting go begins from the element's current position at the speed of the hand, so there is no seam between dragging and settling. A short fast flick commits even when the distance is small; direction of travel decides whether the gesture commits or reverts, not position alone. Why: people judge by intent, and a threshold that ignores speed punishes a confident flick. `L1` · R162 (the flick commits; the rest remains default)
- Land where the gesture is heading. For things that rest at stops (sheets, carousels, snap points), project where the motion would come to rest and choose the nearest stop to that, not to the release point. A small input should give a large, correct output. `L1` · default
- Edges give, they do not wall. Past a natural boundary the element follows less and less the further it is dragged, and returns when released. A hard stop reads as frozen; rising resistance reads as responsive with nothing more to give. `L1` · R162
- Settling does not overshoot by default. Critically damped settling is calm and unobtrusive. A visible bounce stays a playful-tone choice (see `principles/motion.md`), and even there is least wrong where the gesture threw the element; a menu that merely appeared never bounces. Gesture-driven motion should be able to be grabbed and reversed mid-flight. `L1` · default
- Intermediate frames point at the outcome. People predict where something ends up from its trajectory, so an expanding control grows toward the finger and a dismissing sheet leans toward where it will leave, instead of interpolating blindly. `L1` · default
- Read intent before committing. A small movement threshold before choosing a direction, competing gestures tracked in parallel and resolved once intent is clear, and no waiting on a recognizer that only reports a final state (it throws away the live tracking feedback needs). Pay a disambiguation delay, such as waiting to see whether a tap is a double tap, only where the double action exists. `L1` · default
- Feedback in more than one sense follows three tests: the cause is obvious (it fires on the causal event, such as the toggle flipping, and matches the action's physical character); the senses agree in time (sight, sound and touch land on the same frame, since lag between them breaks the illusion); and it earns its place (reserved for meaningful moments such as commit, snap, success and error, since feedback on everything trains people to ignore all of it). It is never the only channel for something the person needs. `L1` · default
- Gestures are judged in the hand. Emulation cannot show sticky hover, touch lag, rubber-banding, safe areas or the keyboard; test on a real, modest device. `L1` · default

## Phone platform layer (web on phones)
> Adopted from field review (emilkowalski/skills, mobile-native). Reasons are the source's. The point: most "it feels janky on my phone" is the platform layer, not the animation.
- Ask the platform what it can do; never guess from the device. Capability queries for hover and pointer precision, never a device name or screen width as a stand-in for touch. Touch and mouse are not exclusive (tablets with trackpads, laptops with touchscreens), so write for both at once. `L1` · default
- Hover styles belong only where hover exists. Touch fakes a hover on the first tap and leaves it stuck until the next tap elsewhere, so a card that lifts on hover stays lifted. Press feedback is what touch users get instead. `L1` · default
- Remove the browser's default tap flash and give every tappable element its own pressed state; that flash is the loudest "this is a website" tell and it competes with your feedback. Never remove it without the replacement. `L1` · default
- "Full height" has more than one meaning on a phone, because the visible area changes as the browser bar shows and hides. An app shell or pinned bottom bar tracks the visible area; a first-screen hero uses the smallest the viewport gets so nothing is ever cut off. Using the largest value for either pushes bottom actions under the browser bar. `L1` · default
- Never disable pinch-zoom to stop the page jumping into an input. The jump happens because the field's text is below the size the browser will accept without zooming, so set the text size, not the zoom lock. Set the keyboard to match the data and let the return key say what it does. `L1` · default
- Paint edge to edge and pad content out of the unsafe areas (notch, home indicator, rounded corners). Fixed bars, bottom navigation, toasts and sheets carry the inset; ordinary page content usually inherits it. `L1` · default
- An app with its own scrolling regions keeps page-level pull-to-refresh and rubber-banding out of the way, and keeps a nested scroller's own bounce without letting the page behind it move. Do not block scrolling with scripted touch handlers to achieve this. `L1` · default
- Controls are not selectable text and content is. Long-pressing a button should not select its label or open a link callout; addresses, error messages and order numbers must stay selectable, so never switch selection off for the whole page. `L1` · default
- The browser bar and status bar take their color from the page, per color scheme, matched to the color at the very top of the page, not the brand color. A mismatch exposes the seam. `L1` · default
- Declaring a phone issue fixed from emulation is a claim you cannot make. Say which fixes were verified from code and which need a device in hand. `L1` · default

## Accent as a signal, and dark surfaces
- Name the events where the accent may appear: primary action, selected item, focus, progress, a highlighted data point, links, and wayfinding labels such as the active section label (R158: beat spreading it over headings, labels, captions and icons, and beat the primary action alone). Reason: an accent is a signal, so if everything has it nothing stands out; spreading it adds busyness; and accent on selection, progress and the active section helps people keep their place. Anything outside that list is neutral. The accent still covers a small share of any one screen, and captions and decoration are never accent-colored just to add color. A tracked-caps eyebrow stays muted (validated, R097 and R130) unless the brand mandates otherwise. `L1` · R158
- Keep the neutral set small and tinted toward the palette's hue: a few text levels (primary, secondary, line) and no stray one-off grays. `L1` · default
- A dark theme is designed, not inverted. Define paired roles (on-surface, on-accent, inverse) and set text explicitly on any dark or colored section, including the footer. Raise elevation by stepping to a lighter surface, not by shadow, unless the brand specifies its own dark elevation method, which then wins (stated preference from Anthony, untested in a round). A scrim is a dark dim of the page, not a white film. Re-measure contrast on the dark theme, including disabled text and dividers. `L1` · default

## Multi-page and route behavior
- One shared set of tokens and components serves every page; pages add only their own layout. If the same token holds two values on two pages, the product has two systems. The navigation set, header and footer are designed once, identical on every page, with the current page marked. `L1` · default
- A route change behaves like a page load: scroll to top (restore position on back), move focus to the new heading or main region, update the document title, and lazy-load images below the first view but never the main hero image. `L1` · default

## Browser surfaces
- The parts of a page you did not draw still carry the design. Theme text selection, the caret color, scrollbars, focus rings, underline offset, and tabular figures in data from the palette; leaving them at browser defaults is a cheap signal the page was assembled, not built. `L1` · default (adopted from field review)
- For a tool-like surface, the brand or concept supplies type, palette, density and at most one signature move. It never supplies the layout, the navigation model or the controls, which stay conventional. `L1` · default (adopted from field review)

## Interface vocabulary
- The screen speaks the user's language. File names, field names, function names, framework or dataset words never appear in the interface, and an aggregate is described by what it means to the user ("most reviewed first"), not how it was computed. `L1` · default
- A single quiet line in the footer (and on detail pages where money is shown) is enough to say content is sample; not a top banner, and not repeated in every section. This is a default; the honesty rules in the content-integrity section still require placeholders to be labelled. `L1` · default

## Shape, layers and icons
- Nested rounded shapes are concentric: the inner radius is the outer radius minus the padding between them (never below a small floor); R159: corners that share a center read as one shape, and equal radii look uneven at the corners. The same radius on a card and on the button inside it reads as a mistake. Let radius grow with the element's size, and drop any radius step no component uses. `L1` · default
- Separate groups, sections and cards with space first, a change of surface second, and a hairline last (R159: nested boxes add noise, space groups without extra lines, fewer borders are calmer). Rows of records in a table or list keep their hairlines (R088 stands). Nested boxes (a card inside a card inside a panel) are a sign grouping is being done with containers instead of gaps. `L1` · default
- Name the stacking order once (base, sticky bar, dropdown, scrim, dialog, popover, toast, skip link) and take every layer from it; no ad hoc z-index numbers in components. `L1` · default
- If a translucent or blurred surface is used at all (it is explicit-request territory), ship an opaque twin for reduced-transparency settings and check text contrast over white, black and a busy photo. `L1` · default
- If translucency is used, its weight encodes role: heavier material separates structure, lighter material lifts controls, larger surfaces read as thicker than small chips. Never stack a light translucent layer on another; legibility collapses. Color sits on a solid layer, not on the see-through one. Dim to focus when the task is modal; offset without a scrim when a panel runs in parallel so the flow is not broken. Where a floating bar overlaps scrolling content, a soft fade where content meets it can replace a hard line (a hairline remains the last resort, R159). With increased contrast requested, move to a near-solid ground with a defined edge. `L1` · default (adopted from field review)
- An icon is used at the size it was drawn for; scaling a small icon up makes it look chunky, so choose or draw a large one. Exception he accepts (stated, not yet a comparison round): scaling a vector icon up for a large slot in a sparse context, keeping its stroke weight matched to the nearby type. Size icons to the line height of the text beside them (R159: a matched icon reads as part of the label, a mismatched one looks unfinished), and center them on the text line, not the cap height. `L1` · default
- Icons that are not the same shape need optical correction: a circle sits visually smaller than a square of the same box (give it more area), and a play triangle centers on its centroid, not its bounding box. `L1` · default
- Selection in a set (nav icons, tabs, filters) uses two cues: a form change (outline becomes filled, or a fill or weight change) plus the accent, so it survives color blindness (his stated answer, not yet a comparison round). For navigation the active item keeps its line (R155, unchanged: only the active item is marked) and adds a second cue, the accent color or a fill, on top; inactive items stay unmarked. Hover and pressed feedback lives on the control's container, not the glyph. `L1` · default
- Label everything in navigation. Icon-only is for roughly a dozen universally understood actions (search, close, more, add, delete, edit, share, settings), each with a tooltip and an accessible name. `L1` · default

## Feedback channels
- Put the message where its cause is, or where the person lands, and keep it there until it has been read (R159, R160). Beside the control that caused it (a Save button gets an inline note); in the place of the thing that changed (an archived row is replaced in place with an Undo link, which collapses after a few seconds); at the top of the page the person lands on after a permanent action (a note that stays). Use a toast only when the cause has left the screen and nothing remains to point at, such as "Link copied" after a menu closes. Reasons: a toast can vanish before it is read or before the person can undo; a message that stays is always seen; a changed button label is easy to miss. This replaces the earlier rule of a toast with Undo for small confirmations. One persistent banner at most for page or system status; a dialog only for a decision that must block. Never make a toast the only channel for an error that stops progress, and let any timed message that carries an action be paused. `L1` · R160
- Honest-interface lint for the machine-detectable cases: a pre-checked consent or marketing box; accept and decline with unequal emphasis; the same request repeated after the user dismissed it; a countdown with no real deadline behind it; decline copy that shames the user; a cancel path longer than the signup path. Treat each as a defect. (This extends the honesty line in `SKILL.md`.) `L1` · default

## AI surfaces (default; queue 23 is not yet answered)
- Mark generated content as generated. Place a source next to the claim it supports, styled differently from body text, and say what it is (a name, not "Source"); show how many sources back a claim when there are several. Sources go next to the claim, not only in a list at the end (his stated answer, not yet a comparison round). `L1` · default
- For high-stakes content (health, money, legal), show uncertainty twice: a plain first-person hedge in the text, plus a High/Medium/Low label beside the answer. A numeric percentage is acceptable only when the number is real, from a measured and calibrated source; never invent one (his stated answers, not yet a comparison round). Do not present a step-by-step reasoning trace as the explanation of why: it can misdescribe how the answer was produced. Keep the voice neutral rather than human-like, so users do not overrate what it can do. `L1` · default
- Give the user control: stop, regenerate, edit, copy and a way to flag a bad answer; every AI action can be undone or corrected. An AI action asks for confirmation only when it is destructive or irreversible (delete, send, pay); everything else just happens, with Undo (his stated answer, not yet a comparison round). While a response streams, a chat view follows the new text until the reader scrolls or touches, then stops and offers a clear "jump to latest" control; long answers and documents never autoscroll (his stated answer, not yet a comparison round); announce streamed text to assistive tech at completion or in chunks, not word by word. Put the caution near the input with an action ("check this answer") rather than a footer disclaimer. `L1` · default

## Excluded
Illustrated empty states, confetti or count-up success moments, spring-based UI motion, pill CTAs, a two-typeface cap, links demoted to unstyled text, neutral near-black dark mode, and visual-tension asymmetry were left out because each collides with a dealbreaker or non-negotiable.

Considered from emilkowalski/skills and not adopted: his fixed easing curves, duration numbers and press-scale value (this repo keeps a moderate, soft-ending ease-out for staged motion, adopted his strong ease-out for anything that answers an action after R164 and R165, and leaves the numbers to tier references; press scale is queue 15); spring-first UI motion and visible bounce (playful tone only); blur to mask crossfades (queue 5); stagger as a general rule (queue 4); translucent chrome as a default (explicit-request territory); and any slightly open tracking on small lowercase text (a dealbreaker here).
